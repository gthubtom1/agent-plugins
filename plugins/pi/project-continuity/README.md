# Project Continuity：项目级续接

把重要决定、取消/更正、失败条件与证据入口留在**当前项目**，让 Pi Web/CLI 新对话或压缩后能恢复。扩展安装一次，项目记录各自独立；没有全局项目数据库、向量服务、自动上传或后台模型费用。

## 正常怎样使用

照常在项目目录打开对话并工作。扩展提供 `continuity_status`、`continuity_search`、`continuity_save`，并给模型一小段保存/恢复规则。遇到重要决定、结论被实测推翻或昂贵分析失败时，模型应增量保存；之后新会话自动读取有界恢复材料。无需每步回复“继续”，也没有新增计划批准门。

第一次显式保存才创建 `.pi/memory/`。普通聊天、启动、只读状态检查不会创建记录。模型可能不主动调用保存工具，所以要区分“扩展已加载”和“记录已落盘”；`/continuity status` 可检查。需要时直接说“把这个决定和依据记录到当前项目，下次继续时沿用”。

- `/continuity` 或 `/continuity status`：看当前项目和记录。
- `/continuity init`：显式初始化当前项目。
- `/continuity adopt`：项目搬家或复制后，保留记录并将这份工作副本接到当前路径；接管前可读，写入会拒绝。
- `/continuity search 关键词`：查询本项目。
- `/continuity off` / `/continuity on`：本会话关闭/开启。

## 文件与当前状态

所有数据位于项目 `.pi/memory/`：项目标记、小份 `MEMORY.md`、主题投影、追加式修订和来源。原始内容是数据，不是新指令。不要把含私有代码或会话摘录的目录自动上传；可按项目备份、或自行选择纳入版本管理。

每个可以独立变更的角色、决定或约束分别使用稳定 id；更新或取消仍写该 id，提供最新项目 revision。撤销时明确保存 `status: cancelled`，其他仍有效的决定保留自己的 `accepted` 状态，不能仅在一条混合记录中改文字。搜索旧别名会返回当前取消/替代状态，历史显式查询才展开旧修订。跨会话并发需要修订检查，不采用“最后写入覆盖”。源文件变了会标记待复核，而不是刷新摘要掩盖变化。

Reverse 原 `scope.md`、`timeline.md`、`workitems.md`、Evidence，以及普通开发的代码/spec/ADR/test 仍是各自事实来源。本扩展只记录指针和续接知识，不批准授权、不另建任务系统、不代替 REA、Spec Kit 或 grilling。

一次工具 succeeded 只说明该步骤结束，不说明业务成功。技术 claim 默认 candidate，不支持用 memory 工具直接写 validated。已初始化项目会在一轮结束时保存最近的模型自述和最近一次工具错误；自述明确标为待核对，工具错误带方法和参数摘要，不猜测根因。同一自述不重复保存。多个 case 未选定时跳过自动摘要，技术记录必须指定 case，避免混入全项目状态。

## 安装与换机

这是独立、自包含的 Pi package。可将本目录放在本机固定位置，在实际 Pi Web 使用的 agent `settings.json` 中把该目录加入 `packages`。它的 package manifest 只声明本扩展，不会启用插件库里的其他重试/人格插件。

组合环境请按 [reverse-workflow-installer](https://github.com/gthubtom1/reverse-workflow-installer) 的冻结 plan 安装。该安装器将单独获取并记录本插件的精确来源、身份和内容摘要，检查配置/恢复归属。项目记录随项目文件夹迁移，插件源码和用户记录互不混淆。

插件库根 package 也声明本插件；不要同时手工复制入口和安装整个库造成双重注册。修改后 reload Pi；当前长对话里已有的错误结论不会被本插件自动证明或删除。

## 设计和边界

- 项目根：已有记忆标记优先，兼容子目录和没有 Git 的样本目录；多个 case 不按最新 mtime 猜测。工作副本/版本不同的结论不默认互用。
- 恢复：每次模型请求读取当前项目状态，默认恢复正文最多 6,000 字符，主题与来源按需查；不整篇读取聊天 JSONL，不更改 Pi 原生压缩。搜索最多返回 12 项，过大的历史改为完整的状态/来源指针，不截出半条取消记录。
- 写入：项目内来源检查、乐观修订校验、独占锁、原子修订事务与可重建投影；日志损坏时停止返回当前事实。过长的显式约束拒绝保存，改用短说明和来源指针，不能默默截断。
- 单个来源文件上限 5 MiB。大二进制或长日志使用小型证据索引作来源，记录实际样本哈希、原始文件路径和操作身份；不把整个样本复制到记忆目录。
- 成本：只使用本地 Node 文件操作及只读 Git 分支查询；不自动调用额外模型，不在 `agent_end` 强制续跑。当前文件日志按记录数线性读取，尚未做数万条记录的性能验收；有界注入不等于读取耗时恒定。
- 不构成强沙箱；扩展与宿主使用相同 OS 权限，文件约束用于避免错误路径和串项目。
- 不保证模型一定记录所有重要内容，或其技术结论一定正确。通过机械校验不等于语义验证，也不等于任意20天真实项目已验收。

## 测试

```text
node --test test/*.test.mjs
```

离线夹具覆盖项目隔离、角色修改取消、历史别名、来源变化、写入冲突、中断事务恢复、有界上下文和 Pi 事件。

真实宿主流程可用 `PI_SDK_DIR=<实际 pi-coding-agent 包目录> node scripts/verify-sdk.mjs` 复验。脚本加载该 SDK 和 bundled CLI，在隔离项目用本地模拟 provider 驱动真实 prompt、compact、tree、reload、resume 和 RPC 命令；不联网，不读取账号或修改用户配置，报告路径打印到终端。模拟 provider 验证生命周期与传给模型的上下文，不证明外部模型一定正确理解。外部模型抽样、实际 Web 页面加载与安装回执另行记录。

实现来源与借鉴边界见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
