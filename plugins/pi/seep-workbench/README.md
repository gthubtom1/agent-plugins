# Seep 专用扩展源码备份（显式选用）

这里保存 Seep 主仓库中已经二开的自有 Pi 扩展，以及它们所需的人设/回退共享库。
目的是让插件仓库也保留更新，不让主仓库和插件备份长期分叉。

## 和通用插件的区别

- 根 `package.json` **不加载这里**。普通插件安装仍只有原来的 6 个扩展。
- 本包包含 8 个 Seep 扩展 + persona/rewind，共 10 个；不是 10 个互不相关的独立插件。
- 提示词扩展包含能力发现与经验维护短提醒；资源路径仍由 Seep 的实际发现链路解析，没有复制固定技能/KB/工具列表。
- 案件记忆/事件、首答、断路器、安全检查、风险回执等依赖 Seep 的规则、工具脚本和工作目录约定。这里只备份插件源码，**不包含完整工作台，更不能保证所有执行通道受控**。
- 通用 `pi-seep-ext` 的手机连接功能仍在原包，本包不新增远程访问，也不修改该功能。

## 安装与升级

**推荐且完整的方式**：让智能体读取 [Seep 主仓库](https://github.com/gthubtom1/SRL) README，
按安装流程探测并部署。Seep 的安装器已经会安装这些扩展及依赖，不需要额外从本仓库再装一次。

本目录是可加载的源码包，供测试、备份和维护；不是换机部署 Seep 的捷径。
只有已部署完整 Seep、明确采用包加载方式并已排除同名自动加载扩展时，才可手工选择它。
不要与根包的 cmd-guard/retry-level/persona/rewind 或 Seep 已部署副本叠加加载。
不要只挑一个 `.ts` 文件复制：保留 `extensions/` 与 `packages/` 的相对布局。

## 来源与维护

`SOURCE.json` 记录本次取自 Seep 的提交、逐文件路径和 SHA256。子包里的 `UPSTREAM.json`
是 Seep 原有的 vendoring 历史，不能用它冒充本次回流后的插件仓库提交。
本次没有同步真实 settings、账号、会话、密钥、样本或用户的案件内容。

之后在 Seep 更新扩展时：先比较通用版是否适用，再更新本目录的完整依赖闭包与 `SOURCE.json`；
通用版适配不能引入隐式跨插件引用。共享 helper 的本地副本需一起更新并通过一致性检查。
详细测试入口和范围见 [同步记录](../../../docs/SEEP-SYNC-2026-11-02.md)。
