# retry-level（Pi Coding Agent 重试档位扩展）

给 **Pi Coding Agent (`@earendil-works/pi-coding-agent`)** 加一个可调档的重试策略：
**菜单切档 + 状态栏常显 + 无限档可随时中断**。

比老版 `pi-infinite-retry` 更实用：那版只有「开/关」，这版有档位、有菜单、状态栏一直显示当前档位。

---

## 📖 为什么需要它

Pi 内核的默认重试上限是 **3 次**。遇到上游网关抖动（`502` / `503` / `504` / `522` / `524`）、
高并发 `429` 限流、或长连接断开（`fetch failed` / `socket hang up` / `other side closed`），
3 次很快耗尽 → **整个回合硬报错中断**，得人工介入。

长时间无人值守的任务（批量采集、大规模重构、挂机调度）最怕这个。

---

## ⚡ 命令

| 命令 | 作用 |
|---|---|
| `/retry` | 打开菜单选档位：**关闭 / 3 / 5 / 10 / 15 / 30 / 无限** |
| `/retry cycle` | 无菜单循环切档（按一次切一档） |
| `/retry <档位>` | 直接切：`off` \| `3` \| `5` \| `10` \| `15` \| `30` \| `infinite` |
| `/retry status` | 查看当前档位 |

**底部状态栏始终显示当前档位** —— 不会再出现「设了 10 次却什么都不显示」。

---

## 🔒 安全设计

| 机制 | 说明 |
|---|---|
| **随时可中断** | 无限档是 **9999 次 + 指数避让**，不是死循环；随时按 **Esc** 中断（pi 自带的重试取消键） |
| **指数退避 + 抖动** | 走 pi 官方底层退避引擎，单次等待上限钳制，不会打爆网关 |
| **智能分类** | 只对**瞬态**网络/网关错误重试；对 `insufficient_quota`（欠费）、`context_length_exceeded`（越界）等**不可恢复**错误立即退出，绝不死循环 |

## 🚀 安装

```bash
# 方式一：从本仓库包装（连同其他自制插件一起）
pi install git:github.com/gthubtom1/agent-plugins@main

# 方式二：手工放文件
cp retry-level.ts ~/.pi/agent/extensions/
# 重启 pi
```

---

## ⚠️ 不要与 `pi-infinite-retry` 同时启用

两者**都注册 `/retry` 命令**，同时启用会冲突。

| | `retry-level`（本插件） | `pi-infinite-retry`（老版） |
|---|---|---|
| 档位 | 7 档菜单 | 只有开/关 |
| 状态栏 | ✅ 常显 | ❌ 无 |
| 循环切档 | ✅ `/retry cycle` | ❌ |
| 建议 | **用这个** | 源码保留作参考 |

## Seep 回流修复（2026-11-02）

设置改为原子写入、回读校验与失败恢复，保留未知字段；坏 JSON 不覆盖，失败不显示假成功。
自定义 agent 目录支持 `~/`。遇明确无法恢复的配额或认证错误时，请求中止当前运行并保存
3 次档位供下次重载生效；生命周期钩子不调用仅命令上下文才有的 `reload()`。

它只调整 **Pi 模型请求重试设置**，不是目标网站、卡密请求、浏览器或 MCP 的通用重试器，
不替代 Seep 的运行时风险预算。没有安装或更改任何第三方依赖。
